# 84부 일정표

감사 84부 회계사들이 폰과 PC에서 함께 쓰는 부서 일정표 웹앱입니다.
스토어 설치 없이 링크로 접속해 "홈 화면에 추가"하면 앱처럼 열립니다(안드로이드·아이폰·PC 공통).

- 접속 주소: https://keuncpa.github.io/sched84/
- 처음 서버를 만드는 방법, 권한 규칙, 운영 방법: [`설치가이드.md`](설치가이드.md)
- 이 문서는 **이어서 개발하는 사람**(다른 PC로 옮긴 본인, 인수받는 사람, AI 도우미)을 위한 안내입니다.

## 한눈에 보기

| 항목 | 내용 |
|---|---|
| 화면 | `index.html` 한 파일 (프레임워크·빌드 없음, 순수 자바스크립트) |
| 호스팅 | GitHub Pages — `main` 브랜치에 올리면 1분쯤 뒤 자동 배포 |
| 서버 | Supabase (Postgres + 로그인 + Edge Function), 무료 요금제 |
| 로그인 | 이메일·비밀번호. 가입 후 **관리자 승인**을 받아야 일정이 보임 |
| 알림 | 웹 푸시. 관리자가 팀원을 배정하면 그 사람 폰으로 알림 |
| 메일 | 비밀번호 재설정 메일은 관리용 Gmail의 SMTP로 발송 |

## 기능

- **달력 / 팀 보기 / 내 일정 / 설정** 4개 탭. 달력은 좌우로 밀어 월 이동
- 일정: 유형, 거래처, 제목, 기간, 메모. 본인 일정만 수정·삭제
- 관리자: 가입 승인, 관리자 지정, 퇴사 처리(과거 일정은 보존), 팀원 배정과 사람별 역할(매니저·인차지·시니어·스탭), 유형·거래처 관리, 구성원 순서(서열) 지정
- 거래처별 색, 거래처별 보기, 거래처 화면(그 거래처의 전체 일정과 배정 인원)
- 엑셀로 내려받기: 부서에서 쓰던 양식(분기 시트 안에 월별 표, 거래처 주간업무 + 사람별 줄)
- "↻ 새로고침" 버튼과 자동 업데이트(새 버전이 올라오면 열려 있는 앱이 스스로 갱신)

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 앱 본체. 스타일·화면·서버 통신·엑셀 만들기가 모두 들어 있음 |
| `config.js` | 서버 주소와 **공개용** 키. 비워 두면 데모 모드 |
| `sw.js` | 서비스 워커. 오프라인 캐시(네트워크 우선)와 푸시 알림 표시 |
| `version.json` | 현재 배포 버전. 앱이 이 값을 보고 스스로 새로고침 |
| `manifest.webmanifest`, `icons/` | 홈 화면 설치용 |
| `supabase.js` | supabase-js 라이브러리를 그대로 넣어 둔 것(수정하지 않음) |
| `schema.sql`, `schema_v2.sql` … `schema_v11.sql` | 서버 테이블·권한 규칙. **번호 순서대로** 한 번씩 실행 |
| `server/notify.ts` | 배정 알림을 보내는 Edge Function(`notify`) 원본 |
| `dev/tests/` | 개발 중에 쓴 화면 자동 점검 스크립트(참고용) |
| `설치가이드.md` | 서버 만들기부터 운영까지의 안내 |

### `index.html` 안의 구조

위에서부터 대략 이 순서입니다. 찾을 때는 괄호 안의 이름으로 검색하면 됩니다.

1. **스타일** — 기본 규칙 뒤에 `겉모습 2: iOS 캘린더풍` 블록이 덮어쓰는 구조. 색은 `:root`의 변수(`--brand` 등)로 조절
2. **설정·상수** — `APP_VERSION`, `DEFAULT_CATS`, `COLORS`, `ROLES`, `HUES`
3. **저장소 계층** — `supaStore(sb)`(실제 서버)와 `demoStore`(이 기기에만 저장). 두 개가 같은 함수 이름을 가짐. 새 서버 기능을 넣을 때는 **둘 다** 고쳐야 데모 모드가 깨지지 않음
4. **상태와 도우미** — `S`(현재 화면·월·주 등), `whoOf`, `bySeniority`, `ec`(일정 색)
5. **알림** — `pushState`, `pushEnable`, `pushCard`
6. **화면 그리기** — `refresh`(가진 내용으로 먼저 그리고 뒤에서 최신화), `viewCal`, `viewTeam`, `viewMine`, `viewSet`
7. **엑셀** — `XL`(xlsx를 직접 만드는 코드), `exportCard`, `deliverFile`
8. **창** — `sheetAt`, `openDay`, `openDetail`, `openClient`, `openForm`, `ask`(확인 창)

## 다른 PC(맥북 등)에서 이어가기

```bash
git clone https://github.com/keuncpa/sched84.git
cd sched84
python3 -m http.server 8000      # http://localhost:8000 으로 열기
```

- 이 상태로 열면 `config.js`에 서버 주소가 들어 있어 **실제 서버**에 붙습니다. 화면만 시험하려면 `config.js`의 `SUPABASE_URL`, `SUPABASE_KEY`를 빈 문자열로 바꾼 사본 폴더를 따로 만들어 여세요(데모 모드). 빈 값으로 바꾼 `config.js`를 올리면 안 됩니다.
- 파일을 더블클릭(`file://`)으로 열면 서비스 워커와 알림이 동작하지 않습니다. 위처럼 로컬 서버로 여세요.
- 올릴 권한은 저장소 주인 계정(또는 초대받은 협업자)에게만 있습니다.

## 고쳐서 배포하는 순서

1. `index.html`을 고칩니다.
2. **세 군데의 버전을 함께 올립니다.** 하나라도 빠지면 폰에 예전 화면이 남습니다.
   - `index.html`의 `APP_VERSION` — 형식은 `날짜.그날 몇 번째 배포.누적 배포 횟수` (예: `2026-11-27.15.40` → `2026-11-27.16.41`). 누적 횟수는 `git rev-list --count HEAD`에 1을 더한 값(이번 커밋이 몇 번째인지)
   - `version.json`의 `v` (위와 같은 값)
   - `sw.js` 맨 위 캐시 이름 `sched84-vN`의 숫자
3. `git commit` 후 `git push origin main`.
4. 1분쯤 뒤 `https://keuncpa.github.io/sched84/version.json`이 새 값인지 확인합니다.
5. 사용자는 앱의 "↻ 새로고침"을 누르거나, 앱을 다시 열면 자동으로 새 버전이 됩니다.

## 서버(Supabase) 쪽 구성

| 구분 | 내용 |
|---|---|
| 테이블 | `profiles`(구성원), `events`(일정), `event_members`(배정·역할), `categories`(유형), `clients`(거래처), `push_subscriptions`(알림 받을 기기) |
| 권한 | 모든 테이블에 RLS. 승인 여부는 `is_approved()`, 관리자 여부는 `is_admin()`으로 판단 |
| 로그인 설정 | 이메일 확인 끔, Site URL = 앱 주소, 메일 발송은 Gmail SMTP |
| Edge Function | `notify` — "Verify JWT with legacy secret" 끔. 호출한 사람의 로그인 토큰으로 DB 함수 `push_targets`를 불러 권한을 확인 |
| 비밀 값 | Edge Functions → Secrets 의 `VAPID_PRIVATE_KEY` 하나 |

**DB 규칙을 바꿀 때**: 기존 파일을 고치지 말고 `schema_v8.sql`처럼 새 번호 파일을 추가한 뒤 Supabase SQL Editor에서 실행합니다. 앱 배포보다 **먼저** 실행해야 합니다(앱이 새 칸을 찾는데 서버에 없으면 오류).

**알림 함수를 바꿀 때**: `server/notify.ts`를 고친 뒤 Supabase 대시보드 → Edge Functions → `notify`에 붙여넣어 다시 배포합니다. 함수 주소에 GET으로 접속하면 `{"vapid":"ok"}`처럼 키 상태를 알려 줍니다(`mismatch`·`missing`·`invalid`면 Secrets의 키를 다시 확인).

## 저장소에 넣으면 안 되는 것

이 저장소는 **공개**입니다.

| 값 | 어디에 두나 |
|---|---|
| Supabase Publishable key, VAPID 공개 키 | `config.js` (공개되어도 되는 값) |
| Supabase Secret key (`sb_secret_…`) | 어디에도 적지 않음. 필요하면 대시보드에서만 사용 |
| VAPID 비공개 키 | Supabase Edge Functions → Secrets 에만 |
| Gmail 앱 비밀번호 | Supabase 로그인 설정의 SMTP 칸에만 |
| 일정·거래처·구성원 자료, 백업 파일 | 이 저장소에 올리지 않음(올린다면 비공개 저장소) |

## 점검 스크립트 (`dev/tests/`)

개발하면서 쓴 Playwright(파이썬) 스크립트입니다. 화면을 실제로 눌러 보며 오류와 잘못 찍힌 글자를 확인합니다.

- 데모 모드 사본을 `8771` 포트, 저장소 폴더를 `8772` 포트로 띄워 두고 실행하는 것을 전제로 합니다.
- 스크립트 안의 크롬 경로(`/usr/bin/google-chrome`)와 주소는 실행 환경에 맞게 바꿔야 합니다.
- 자주 쓴 것: `t18.py`(모든 화면 훑기), `t8.py`(실제 서버 흉내), `t25.py`(탭 전환 속도), `t26.py`(좌우 밀기), `t27.py`(엑셀 내려받기), `t30.py`(구성원 순서), `t31.py`(상세 화면의 탭 바)
- `mock_auth.sql`은 로컬 Postgres에서 권한 규칙을 시험할 때 Supabase의 로그인 부분을 흉내 내는 용도입니다.

## 지금 상태 (2026-11-27 기준)

- 배포 버전은 앱 [설정] 맨 아래와 `version.json` 참고, 서버에는 `schema.sql`부터 `schema_v11.sql`까지 적용됨
- 기존 엑셀 일정표의 2024년 4분기 ~ 2027년 1분기 일정을 옮겨 넣음(`events.source = 'excel-2611'`). 옮길 때 쓴 SQL과 되돌리기 SQL은 이름이 들어 있어 저장소에는 두지 않음
- 실제 기기에서 확인된 것: 가입·승인, 일정 추가, 팀원 배정, 배정 알림, PC에서 엑셀 내려받기, 구성원 순서 바꾸기
- 실제 기기에서 아직 확인하지 못한 것: 폰에서 엑셀 저장·공유, 달력 좌우 밀기 감도, 아이폰 날짜 입력 칸 모양

### 보류·미정

| 항목 | 상태 |
|---|---|
| 미가입 팀원 연결 | 이름만 먼저 등록해 둔 팀원(`profiles.pending`)이 가입하면, 관리자가 [설정] → 구성원의 승인 대기 줄에서 "기존 이름과 연결"을 골라 일정을 넘겨받게 함 |
| 2024년 3분기 이전 일정 | 옮기지 않음(원본 엑셀의 숨김 시트). 필요하면 같은 방식으로 추가 가능 |
| 거래처 색을 기존 엑셀과 맞추기 | 보류. 기존 엑셀은 거래처별 색이 고정돼 있지 않음. 맞추려면 색 직접 지정 기능이 필요 |
| 주간 자동 백업 + 일시정지 방지 | 미정. 비공개 저장소의 예약 실행으로 매주 전체 자료를 저장하는 방안을 제안해 둠 |
| 홈 화면 아이콘 | 예전 남색 그대로. 새 디자인 톤으로 바꿀지 미정 |

### 알아둘 점

- 무료 요금제는 일주일 동안 사용이 없으면 프로젝트가 일시정지되고, 자동 백업이 없습니다.
- 저장소와 Supabase 프로젝트가 한 사람의 개인 계정 소유입니다. 담당자가 바뀌면 두 곳 모두 넘겨야 합니다.
- 감사 대상 회사명이 외부 서버에 저장됩니다. 법인 정보보안 규정은 `설치가이드.md` 마지막 절을 참고하세요.
